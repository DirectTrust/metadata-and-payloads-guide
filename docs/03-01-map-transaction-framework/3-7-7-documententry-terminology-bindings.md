# 3.7.7 DocumentEntry Terminology Bindings

The following bindings classify the included information objects and describe their authors, clinical settings, and context.

| Metadata element | ValueSet or fixed value | Binding strength | Application rule |
| --- | --- | --- | --- |
| classCode | LOINC Document Ontology http://loinc.org/vs/loinc-document-ontology | Extensible | Select the broader classification appropriate to the information object. Do not substitute a MAP transaction code for an information-object class. Document Category alignment is governed by the declared exchange policy; see Chapter T. |
| typeCode | LOINC Document Ontology http://loinc.org/vs/loinc-document-ontology | Extensible | Select the specific type of information object. A Transaction Definition may establish a fixed code. Retain an explicitly defined DirectTrust temporary code where LOINC DO lacks the needed concept. For clinical documents, this is Document Type as defined in Chapter T. |
| formatCode | IHE FormatCode ValueSet http://ihe.net/fhir/ihe.formatcode.fhir/ValueSet/formatcode DirectTrust FormatCode ValueSet http://objects.directtrust.org/standards/terminology/ValueSet/DTFormatCodeVS | Extensible | Use a code for the actual technical format and applicable content profile. A code from either listed set is acceptable. Transaction Definitions specify applicable format codes for their artifacts. |
| languageCode | Common Languages http://hl7.org/fhir/ValueSet/languages | Extensible | Represent the actual language using the applicable BCP 47 language tag. Do not derive a fixed language solely from the use case. |
| authorRole | Care Team Member Function http://cts.nlm.nih.gov/fhir/ValueSet/2.16.840.1.113762.1.4.1099.30 | Extensible | Represents the patient- or act-specific function when known. Do not substitute professional occupation or specialty for that function. |
| authorSpecialty | NUCC Provider Taxonomy http://hl7.org/fhir/ValueSet/provider-taxonomy C80 Practice Setting Codes (SNOMED CT Medical Specialty) http://hl7.org/fhir/ValueSet/c80-practice-codes | Extensible | A code from either ValueSet is acceptable. Preserve the code system of each supplied specialty. Multiple applicable specialties may be carried. |
| practiceSettingCode | C80 Practice Setting Codes (SNOMED CT Medical Specialty) http://hl7.org/fhir/ValueSet/c80-practice-codes | Extensible | Describes the clinical practice setting associated with creation of the information. Preserve its distinction from author function and facility type. |
| confidentialityCode | Confidentiality http://terminology.hl7.org/ValueSet/v3-Confidentiality | Extensible | Use the classification applicable to the source information. N is not a universal default; a use case may explicitly establish a fixed value where appropriate. |
| healthcareFacilityTypeCode | ServiceDeliveryLocationRoleType http://terminology.hl7.org/ValueSet/v3-ServiceDeliveryLocationRoleType Healthcare Service Location Type Combined http://cts.nlm.nih.gov/fhir/ValueSet/2.16.840.1.113762.1.4.1267.31 CMS Place of Service Codes http://terminology.hl7.org/ValueSet/CMSPlaceOfServiceCodes | Extensible | A code from any of these three ValueSets is acceptable. Describe the facility or service location applicable to the clinical activity; retain the selected code system. |
| referenceIdList ContextInstance TypeCode | DirectTrust Context TypeCode Value Set http://objects.directtrust.org/standards/terminology/ValueSet/DTContextTypeCodeVS | Extensible | Use the common ContextInstance type binding. Applicable instance identifiers SHALL remain consistent with the Task and SubmissionSet declarations. |

The LOINC Document Ontology binding applies to information-object classification, including non-CDA artifacts where the concept is appropriate. Temporary classification codes explicitly identified by a Transaction Definition remain permitted when the needed concept is not represented in LOINC DO. Terminology binding does not change the source-derivation rules or authorize fabricated clinical metadata.

Terminology references: LOINC’s published Document Ontology ValueSet is documented at https://loinc.org/kb/api/fhir/valueset. FHIR R4 binding semantics are defined at https://hl7.org/fhir/R4/terminologies.html. The author-function and facility-type ValueSets retain the canonical identities of the sets identified in the Document Categories worksheet; dated terminology-server links are access locations rather than replacement canonical identifiers.
