# 0.3 How to Use This Framework

Readers should begin with Chapters 1 and 2 to understand the MAP architectural model, the roles and responsibilities of participating parties and technical actors, and the distinction between Generalized Transaction Definitions (GenTXDefs) and Use-Case Transaction Definitions (UCTXDefs). Together, Chapters 1 and 2 establish the **MAP Use Case Framework**.

Chapter 3 establishes the **MAP Transaction Framework**, defining the common architecture and technical requirements applicable to MAP transactions. The **Reusable Transaction Catalog (RTC)** complements this chapter by providing governed GenTXDefs, including transaction patterns generalized from experience developing MAP Use-Case Implementation Guides (UC IGs). Chapter 4 explains the purpose and function of a **Direct Endpoint Capability Statement**, including its role in communicating endpoint capabilities for interoperable exchange. Chapter 5 provides high-level implementer guidance for applying the Framework as a whole. The appendices provide technical explanations, mappings, terminology, examples, and references.

The MAP Framework is designed to support individuals and organizations authoring Implementation Guides that use Direct for specific business use cases. The **MAPUC Author Kit** supplies supporting materials, templates, instructions, and validation methods—including access to the Framework and RTC—to help authors document business objectives, scenarios, information exchange workflows, and the metadata, payload, and processing requirements implementers must satisfy. Its Chapter 2 Workbook helps authors progress from **Information Exchange Objectives → Business Scenarios → Responsible Organizations → Required Information Exchanges → RTC Analysis → Transaction Architecture Outputs**. This analysis starts with business needs, not the catalog's existing inventory.

Each MAP UC IG establishes its own set of UCTXDefs in its Chapter 3. These definitions typically select and constrain applicable GenTXDefs from the RTC to specify vocabulary bindings, cardinalities, actor responsibilities, and processing requirements. A UC IG may also introduce new UCTXDefs where existing GenTXDefs do not adequately address the required exchanges. Following publication, new transaction patterns may undergo generalization and approval through **DirectTrust's MAP Framework Consensus Body**, potentially producing new GenTXDefs for inclusion in the RTC. Publication does not itself confer RTC status.

Authors use the MAPUC Author Kit to develop and validate UC IG artifacts. Implementers apply normative requirements of the applicable UC IG, including its UCTXDefs and inherited Framework and GenTXDef requirements. Authoring instructions and catalog governance requirements are distinct from implementing actors' exchange conformance obligations.

A GenTXDef's presence in the RTC does not make it applicable to a use case unless selected by that UC IG. Likewise, a placeholder transaction in a workflow model is not a complete transaction specification and does not independently establish implementation conformance requirements.
