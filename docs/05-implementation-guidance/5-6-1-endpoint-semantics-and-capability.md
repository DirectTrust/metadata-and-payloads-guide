# 5.6.1 Endpoint Semantics and Capability

A discovery process can locate the Information Recipient’s organizational affiliation and an endpoint designated for the use case. For example, Dr. Smith may have an individual Direct address while the organization provides a preferred endpoint for the required notifications. Applicable routing rules select that organizational endpoint as the Routing Target. If no suitable organizational endpoint is available, the individual address may be used when its capabilities and the applicable rules support the exchange. Retain the Information Recipient’s identity separately from the Routing Target. The DirectTrust Directory is the authoritative source for discovering an endpoint’s CapabilityStatement; the discovered CapabilityStatement is authoritative for declared transaction and Technical Actor Role capabilities. SERV_DESC is human-readable information and does not establish capability. Apply Chapter 4’s discovery requirements.

Resolve the Information Recipient and an authorized Routing Target before constructing representation-specific metadata. The Endpoint Capability Statement declares supported transactions, Technical Actor Roles, metadata representations, information-object options, and workflow status responsibilities. Select a mutually supported metadata representation using Chapter 4’s preference rules, and confirm JSON or XML support where applicable. TX8 normally uses the originating transaction’s metadata representation unless an explicitly established agreement specifies otherwise.

Capability declarations are testable assertions. A declared transaction, Technical Actor Role, and exchange-option combination asserts support for the corresponding functional requirements. Sender Actor and Receiver Actor capabilities, including those for TX8, are declared independently. Supporting an originating transaction does not universally require TX8 Sender Actor or Receiver Actor support; additional obligations may arise under the applicable Transaction Definition or exchange agreement. A separately labeled development-target CapabilityStatement may plan comprehensive testing-tool coverage, but it is not evidence of deployed capability and SHALL NOT be used for operational Directory discovery. Routing or relay capability alone does not authorize an intermediary to accept or reject a structured payload for the Information Recipient Organization.
